# Prompt Builder v2 — 強化改動說明

## 架構層面改動

### 1. DRY 原則：抽出共用片段
**問題**：原版中英文各自維護完整 prompt，角色設定重複了 4 次（兩函式 × 兩語言）。
**改動**：抽出 `getIdentity()`、`getStyleRules()`、`getGuardrails()` 三個共用函式。
**效果**：改一處即同步四個版本，維護成本降低 ~60%。

### 2. XML 標籤取代 Markdown Heading 做分區
**問題**：原版用 `## 人格設定`、`## 風格` 等 markdown heading 分區，但 heading 在 LLM 眼中和正文的區隔不夠強。
**改動**：改用 `<identity>`、`<style_rules>`、`<guardrails>`、`<task>`、`<chart_data>` 等語義標籤。
**原因**：
- XML 標籤在 Claude/GPT 系列中有更強的「分區邊界」效果
- 模型更不容易把「規則區」和「資料區」混淆
- `<chart_data>` 明確告訴模型「以下是輸入資料，不是指令」

### 3. 分層優先級：Identity → Style → Guardrails → Task → Data
**問題**：原版把禁止規則放在中間，容易被前後的長文淹沒。
**改動**：按照 LLM 注意力分佈（開頭和結尾最強）重排：
- 開頭：角色設定（最穩定，最先建立）
- 中間偏前：風格規則 + 禁止規則（重要但不常變）
- 中後：任務指令（每次不同）
- 結尾前：資料（每次不同）
- 結尾：開場白（觸發生成）

## 內容層面改動

### 4. 英文版補齊所有規則
**問題**：中文版有的規則，英文版大量缺失：
- 禁止提及「雙魚座」 → 英文版完全沒有
- 禁止條列式 → 英文版沒有
- 敘事指引 → 英文版只有一句「將...融合成一個完整的性格畫像」
- 資料缺失的 fallback → 英文版沒有

**改動**：英文版 `<guardrails>` 完整對齊中文版所有 5 條規則。

### 5. 禁止規則精簡化
**問題**：原版用大量 emoji（❌✅）和重複範例：
```
- ❌ 「雙魚座的我」
- ❌ 「身為雙魚座」
- ❌ 「我是雙魚座」
- ❌ 任何形式的「雙魚座」自稱
```
這 4 行說的是同一件事，浪費 token 且 emoji 對模型沒有語義強化效果。

**改動**：壓縮為一條規則 + 正反例各一：
```
1. 絕對禁止提及「雙魚座」來形容自己
   - 錯誤：「雙魚座的我」「身為雙魚座」
   - 正確：直接用「我」「佩璇」
```

### 6. 「篇幅比例」取代「Token 數字」
**問題**：原版寫 `~100 tokens`、`~600 tokens`、`~800-1200 tokens`。
- LLM 對自己輸出了多少 token 沒有精確感知
- 「600 tokens」對模型來說是個抽象數字

**改動**：改用百分比 + 語義權重：
```
- 星曜對稱：約 5% — 一句話帶過
- 四化飛星：約 35% — 找出壓力匯聚點
- 預測：約 60% — 重頭戲
```
**原因**：比例 + 「重頭戲」這種語義提示，比 token 數字更能影響模型行為。

### 7. Few-shot Example 改為骨架式
**問題**：原版的完整範例約 300+ 字，佔大量 prompt token，且：
- 模型容易過度模仿範例的具體措辭
- 範例中的假資料（「紫微天府對宮」「入度3」）可能誤導模型

**改動**：改為 `<example_skeleton>`，只保留結構骨架和 placeholder：
```
「好我看看～你現在走的是 XX 大運，[用一個比喻描述這個階段的能量]。
我跟你說喔，[指出中心性最高的宮位和影響]。...」
```
**效果**：
- 示範敘事流程，不示範具體內容
- 省約 40% 的 example token
- 減少模型「鸚鵡學舌」複製範例措辭的傾向

### 8. 新增 Edge Case Fallback
**問題**：如果輸入的 markdown 缺少某項資料（例如沒有紫微命宮），模型可能會捏造。
**改動**：在 guardrails 中加入：
> 禁止捏造資料中不存在的內容 — 如果某項資料缺失，用「這部分我看不太清楚～」帶過

在 task 中也加入：
> 若某項資料缺失，簡單說「這部分我看不太清楚～」然後繼續

### 9. 敘事流程明確化
**問題**：原版說「將...融合成一個完整的性格畫像」但沒有指定順序。
**改動**：給出明確的 4 步敘事流程：
1. 從大運開場 → 2. 過渡到四化 → 3. 一句帶過星曜 → 4. 預測高潮
**原因**：LLM 在有明確步驟時，輸出的結構品質顯著提升。

## Token 效率

| 項目 | 原版（中文 advanced） | 新版 |
|------|----------------------|------|
| 角色設定 | ~180 tokens | ~120 tokens（精簡） |
| 禁止規則 | ~200 tokens（含大量 emoji） | ~100 tokens |
| Few-shot | ~350 tokens（完整範例） | ~150 tokens（骨架） |
| 任務指令 | ~400 tokens（含重複說明） | ~250 tokens |
| **估計總節省** | — | **約 30-35% prompt tokens** |

## 遷移注意事項

1. **函式簽名不變**：`buildAnalysisPrompt(markdown, locale)` 和 `buildAdvancedAnalysisPrompt(markdown, locale)` 介面完全相容
2. **`hasYearlyForecast` 偵測邏輯不變**：仍然用 `markdown.includes('未來半年運勢') && markdown.includes('立春')`
3. **如果你有其他 locale**：只需在各 `get*()` 函式中加 `else if` 分支
